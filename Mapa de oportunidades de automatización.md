# Actividad autodidacta: Mapa de oportunidades de automatización :map:

**Unidad:** 1. TDTA y sistemas de automatización
**Modalidad:** Trabajo individual previo y revisión presencial
**Tiempo estimado de trabajo autónomo:** 2 a 3 horas
**Tiempo de revisión en clase:** 1 hora
**Producto:** Mapa individual con tres oportunidades de automatización
**Ponderación:** Insumo para el producto de la Unidad 1, cuyo valor es 5 % del curso.

## Objetivo :rocket:

Al finalizar la actividad, el estudiante identificará oportunidades de automatización en procesos de su entorno, distinguiendo proceso, planta y sistema automatizado, y considerando la integración disciplinaria, la ética, la seguridad y el impacto de una posible intervención.

# Instrucciones para el estudiante

## Parte 1. Comprender la ruta TDTA I–V

**Tiempo estimado: 20 minutos**

Revisa la siguiente ruta general:

| Taller   | Pregunta orientadora                                 | Producto esperado                    |
| -------- | ---------------------------------------------------- | ------------------------------------ |
| TDTA I   | ¿Qué proceso necesita mejorarse y por qué?           | Diagnóstico y propuesta conceptual   |
| TDTA II  | ¿Qué fundamentos y alternativas permiten resolverlo? | Investigación y diseño inicial       |
| TDTA III | ¿Cómo se organizará y desarrollará la solución?      | Planeación y diseño detallado        |
| TDTA IV  | ¿Cómo se construye, integra y prueba?                | Prototipo funcional y depurado       |
| TDTA V   | ¿Cómo se valida, documenta y transfiere?             | Solución validada y expediente final |

Después responde brevemente:

1. ¿Por qué no es conveniente comenzar inmediatamente a construir un prototipo?
2. ¿Qué información debe producir TDTA I para facilitar la continuidad del proyecto?
3. ¿Qué consecuencias tendría seleccionar un proyecto al que el equipo no tendrá acceso?
4. ¿Por qué el mismo proyecto puede requerir varias disciplinas de ingeniería?

Extensión esperada: entre cinco y ocho líneas por respuesta.

## Parte 2. Revisar los conceptos centrales

**Tiempo estimado: 25 minutos**

Lee las siguientes definiciones:

### Proceso

Conjunto de actividades o transformaciones mediante las cuales unas entradas se convierten en resultados.

Ejemplos:

* Llenado de un tanque.
* Riego de un cultivo.
* Clasificación de piezas.
* Regulación de temperatura.
* Transporte de materiales.
* Registro de variables ambientales.

### Planta

Parte física del sistema sobre la que se mide o actúa.

Puede estar constituida por:

* Máquinas.
* Tanques y tuberías.
* Motores y mecanismos.
* Hornos.
* Invernaderos.
* Bandas transportadoras.
* Instalaciones eléctricas o hidráulicas.

### Sistema automatizado

Integración de elementos que permiten medir, decidir, actuar, supervisar o proteger un proceso.

Puede incluir:

* Planta o proceso físico.
* Sensores.
* Acondicionamiento de señales.
* Controlador.
* Actuadores.
* Alimentación y potencia.
* Comunicaciones.
* Interfaz del operador.
* Elementos de seguridad.
* Software.

Responde:

1. ¿Cuál es la diferencia entre proceso y planta?
2. ¿Por qué una aplicación móvil, por sí misma, no necesariamente constituye un sistema automatizado?
3. ¿Qué componentes, además del software, pueden ser necesarios para automatizar un proceso?
4. ¿Qué función conserva el operador dentro de un sistema automatizado?

## Parte 3. Observar procesos del entorno

**Tiempo estimado: 30 minutos**

Selecciona al menos tres contextos a los que tengas acceso.

Puedes considerar:

* Laboratorios.
* Talleres.
* Invernaderos.
* Viviendas.
* Comercios.
* Instalaciones universitarias.
* Sistemas de agua o energía.
* Procesos de manufactura.
* Movilidad y estacionamientos.
* Monitoreo ambiental.
* Atención a personas con discapacidad.

En cada contexto observa un proceso y registra:

* ¿Qué actividad se realiza?
* ¿Quién la realiza?
* ¿Qué entradas necesita?
* ¿Qué resultado produce?
* ¿Qué decisiones se toman?
* ¿Qué variables intervienen?
* ¿Qué se hace manualmente?
* ¿Dónde ocurren errores, retrasos, riesgos o desperdicios?
* ¿Qué evidencia tienes de que el problema existe?

La evidencia puede ser:

* Fotografía autorizada.
* Registro de observación.
* Entrevista breve.
* Medición inicial.
* Documento o formato utilizado.
* Descripción de un incidente.
* Frecuencia aproximada del problema.

No debes intervenir, modificar ni operar equipos sin autorización.

## Parte 4. Formular tres oportunidades

**Tiempo estimado: 45 minutos**

Para cada proceso, redacta la oportunidad con la siguiente estructura:

> En **[contexto]**, el proceso de **[actividad]** presenta **[problema observable]**, lo cual provoca **[consecuencia]**, de acuerdo con **[evidencia inicial]**. Una función de automatización potencial sería **[medir, detectar, registrar, alertar, supervisar, controlar, secuenciar, accionar, proteger u optimizar]**.

### Ejemplo

> En el invernadero, el riego se activa mediante un horario fijo sin considerar la humedad del suelo. Esto puede ocasionar consumo innecesario de agua y condiciones inadecuadas para el cultivo. La situación se identificó mediante la observación del procedimiento de riego y una entrevista con el responsable. Una función potencial de automatización sería medir la humedad y regular el suministro de agua.

No propongas todavía marcas, modelos ni componentes definitivos.

# Parte 5. Analizar la integración disciplinaria

**Tiempo estimado: 20 minutos**

Para cada oportunidad identifica qué áreas podrían intervenir y explica brevemente su aportación.

| Área                    | Pregunta orientadora                                                    |
| ----------------------- | ----------------------------------------------------------------------- |
| Mecánica                | ¿Se requiere estructura, movimiento, transmisión o modificación física? |
| Electricidad y potencia | ¿Cómo se alimentarán y protegerán los equipos?                          |
| Instrumentación         | ¿Qué variables deben medirse y con qué principio?                       |
| Electrónica             | ¿Se requiere acondicionamiento, adquisición o procesamiento de señales? |
| Control                 | ¿Qué comportamiento debe regularse o secuenciarse?                      |
| Programación            | ¿Qué lógica, procesamiento o interfaz podría necesitarse?               |
| Comunicaciones          | ¿Se necesita transmitir información entre dispositivos?                 |
| Seguridad               | ¿Qué peligros deben evitarse?                                           |
| Mantenimiento           | ¿Cómo se inspeccionará, reparará o calibrará el sistema?                |

No es necesario que todas las áreas estén presentes en las tres oportunidades. Debes seleccionar solamente las que sean pertinentes.

# Parte 6. Revisar ética, seguridad e impacto

**Tiempo estimado: 20 minutos**

Para cada oportunidad responde:

1. ¿Quién se beneficiaría?
2. ¿Quién podría resultar afectado?
3. ¿Qué riesgos podrían presentarse para las personas?
4. ¿Qué riesgos podrían presentarse para el equipo o el proceso?
5. ¿Qué ocurriría si falla un sensor, actuador o controlador?
6. ¿Debe existir operación manual o parada de emergencia?
7. ¿Se recopilarían datos de personas?
8. ¿Podría producirse un impacto ambiental?
9. ¿El personal necesitaría capacitación?
10. ¿La propuesta sustituye una actividad humana o apoya la toma de decisiones?

* 5: muy alto.

# Revisión presencial de una hora

## 1. Verificación conceptual

**10 minutos**

Aplicar cinco preguntas breves:

1. ¿Qué diferencia existe entre proceso y planta?
2. ¿Qué elementos integran un sistema automatizado?
3. ¿Cuál es el propósito principal de TDTA I?
4. ¿Por qué no se debe comenzar por seleccionar tecnología?
5. ¿Qué función puede conservar el operador?

## 2. Revisión entre pares

**15 minutos**

En parejas intercambian sus mapas y responden:

* ¿El problema está claramente descrito?
* ¿Existe evidencia?
* ¿Se identifica una variable?
* ¿La oportunidad requiere realmente automatización?
* ¿Se están ignorando riesgos?
* ¿La solución propuesta aparece demasiado pronto?

## 3. Discusión por equipos

**15 minutos**

Los integrantes presentan sus oportunidades individuales. El equipo identifica:

* Coincidencias.
* Procesos a los que tienen acceso.
* Oportunidades con mayor relación con la carrera.
* Información que debe investigarse.
* Dos o tres candidatas para continuar explorando.

Todavía no es necesario elegir el proyecto definitivo.

## 4. Presentaciones rápidas

**12 minutos**

Cada equipo dispone de dos minutos para presentar:

* Una oportunidad.
* El problema observado.
* La variable principal.
* La función de automatización.
* La principal incertidumbre.

## 5. Retroalimentación y cierre

**8 minutos**

El docente aclara errores comunes y establece la transición hacia la Unidad 3:

> El mapa de oportunidades es una hipótesis inicial. La siguiente etapa consiste en observar y diagnosticar el proceso antes de aprobar el proyecto.
